# Google Antigravity CLI Provider Design

AI Quota will track Google Antigravity CLI through its documented custom status-line command. The CLI sends a JSON payload to the command on standard input whenever its state changes. Its optional `quota` object maps model or bucket identifiers to `remaining_fraction`, `reset_time`, and `reset_in_seconds`. AI Quota will not invoke private RPCs, inspect Antigravity credentials, or scrape the TUI.

Enabling tracking will install the current AI Quota executable as a dedicated bridge and update `~/.gemini/antigravity-cli/settings.json`. The installer will preserve the existing `statusLine` value and create a timestamped settings backup before writing. The configured bridge will receive the payload, cache only normalized quota data under AI Quota's application-support directory, then execute the previous status-line command with the original payload. If no previous command exists, it will emit a compact Antigravity quota summary. Disabling tracking will restore the exact previous value, and it will refuse to overwrite settings changed by another application after installation.

Antigravity quotas are model-specific and are not limited to AI Quota's existing session and weekly windows. Each normalized window will therefore carry a stable bucket ID and display label while preserving the existing `session` and `weekly` identifiers for Codex and Claude Code. The Antigravity parser will create one window per valid quota entry, convert remaining fraction to used percentage, use Google's reset timestamp, reject malformed or empty payloads, and avoid caching identity, workspace, transcript, or conversation fields.

The service will load and persist the Antigravity cache like the Claude connector. The tray will add Google Antigravity to provider setup, support enable/disable actions, and render a dynamic list of quota buckets. Alerts and the menu-bar summary will evaluate every active bucket and select the lowest remaining percentage. Tests will cover parsing, multiple buckets, invalid data, cache writes, previous-command pass-through, exact settings restoration, changed-settings protection, provider errors, and tray visibility. Full `go test`, race, vet, formatting, and build checks will verify the integration.
